## Admisión

| Recurso | Default | Adquisición | Liberación |
|---|---:|---|---|
| TCP/HTTP aceptado | 128 | accept | cierre de Connection |
| WebSocket | 64 | handshake /lupa válido antes de 101 | cierre del transporte |
| Sesión LUPA | 32 | HELLO válido | LupaSession.onClosed |

Una conexión leyendo HTTP no consume sesión. Un WebSocket esperando HELLO sí consume
capacidad WebSocket, pero no sesión. Sin capacidad WebSocket se responde HTTP 503
antes del upgrade. Sin capacidad de sesión, HELLO recibe LIMIT_EXCEEDED y cierre 1013.

## Ejecutores y lecturas

| Trabajo | Threads default | Cola default | Saturación |
|---|---:|---:|---|
| Estado/HTTP general | hasta 8 | 256 | rechazo |
| Teselas publicadas | hasta 4 | 64 | rechazo |
| Catálogo/manifiesto de OPEN | hasta 2 | 32 | rechazo |

No se usa CallerRunsPolicy. TileReadAdmission limita globalmente a 8 las lecturas de
tesela admitidas. La espera es no bloqueante y FIFO, con como máximo un waiter por
plan y una cola global acotada al máximo de sesiones. Invalidar una VIEW cancela su
waiter; un callback tardío no reactiva un plan antiguo.

## Caché JPEG comprimida

CompressedTileCache es global y compartida por todas las sesiones.

- 128 MiB de JPEG residente por defecto.
- Desalojo LRU.
- Clave imageId + imageVersion + z + x + y.
- Solo almacena teselas publicadas que ya pasaron PublishedTileReader.
- No almacena errores, originales ni bitmaps decodificados.
- Versiones distintas nunca comparten entrada.
- Cada consumidor recibe un handle independiente y no comparte estado mutable de
  ByteBuffer.

residentBytes cuenta solo entradas todavía residentes. Si una entrada es desalojada
mientras otra parte conserva su JPEG, retainedEvictedBytes mantiene esos bytes
contabilizados hasta que se libera el último handle. Un desalojo, por tanto, no se
presenta como memoria inmediatamente liberada cuando todavía hay referencias.

No se deduplican misses simultáneos en este bloque. Dos misses pueden leer la misma
tesela, pero su número permanece acotado por TileReadAdmission; al insertar, una
carga duplicada reutiliza la entrada que ganó la carrera.

## Bytes comprimidos fuera de caché

TransientBufferBudget contabiliza los envelopes TILE ya preparados y retenidos por
la salida WebSocket. El default es 16 MiB.

La reserva usa el tamaño exacto 4 + header JSON + JPEG antes de asignar el envelope.
Se libera al completar la escritura, cancelar una escritura no comprometida, rechazar
el envío o cerrar la conexión. La configuración exige presupuesto para al menos un
TILE máximo por sesión activa.

## Estimación de memoria administrada

No representa heap total, memoria nativa, buffers del SO ni RSS.

| Componente | Cota/default |
|---|---:|
| JPEG residentes en caché | 128 MiB |
| envelopes TILE fuera de caché | 16 MiB |
| payloads de lecturas admitidas | hasta 8 x 256 KiB como orden de magnitud |
| lectura WebSocket | 8 KiB por WebSocket |
| cabecera HTTP | hasta 16 KiB + buffer de lectura por conexión |
| selección | hasta 512 descriptores por sesión |
| entregas | hasta 16 por sesión, además de la ventana negociada |

retainedEvictedBytes debe sumarse al interpretar JPEG todavía referenciados.
No se incluyen objetos Java, stacks, clases, ImageIO, buffers nativos ni SO/RSS.

## Bloque 3 — turnos y cliente sin RELEASE

Un **turno** representa como máximo una tesela admitida para una sesión. La sesión
puede tener como máximo un turno activo o en espera dentro de `TileReadAdmission`.
Los turnos en espera se conceden FIFO. Al terminar una lectura, su permiso se
transfiere al siguiente propietario elegible antes de que la sesión que acaba de
leer pueda monopolizar la admisión.

Una lectura lenta mantiene solamente su propio turno; no bloquea el planificador
global. Con varios permisos globales, distintas sesiones pueden leer en paralelo,
pero una única sesión no puede ocupar más de uno de esos permisos a la vez.

La prioridad **dentro** de cada sesión sigue siendo la definida por
`ViewPlanner`/`PlannedTileCursor`: miniatura inicial cuando corresponde,
contexto mínimo, foco visible y después el resto visible. El coordinador global no
reordena las teselas de una sesión; únicamente arbitra qué sesión obtiene el
siguiente turno de lectura.

### Cliente que no devuelve RELEASE

Los créditos siguen siendo la autoridad. Cuando el cliente no devuelve RELEASE:

- las entregas confirmadas consumen la ventana negociada;
- no se restablece saldo artificialmente;
- al no caber la siguiente tesela se conserva como máximo una tesela preparada por
  plan, que es el margen explícito ya acotado;
- no se siguen solicitando lecturas mientras esa tesela espera crédito;
- otras sesiones continúan obteniendo turnos y pueden llegar a DONE.

La prueba determinista de Bloque 3 usa dos sesiones, una admisión global de una sola
lectura y un ejecutor de disco controlado. Comprueba la secuencia observable
A-B-A y, por separado, que una sesión que retiene RELEASE se detiene con el
invariante `freeWindowBytes + reservedBytes = negotiatedWindowBytes` mientras la
otra sesión completa su recorrido.
