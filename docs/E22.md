# E22 — Concurrencia y recursos

## Estado

Implementación en curso. Este documento distingue límites de diseño de resultados medidos.
E22 no declara todavía la campaña de carga de E23/E24.

## Admisión

La admisión tiene tres presupuestos diferentes:

| Recurso | Default | Momento de adquisición | Liberación |
|---|---:|---|---|
| TCP/HTTP aceptado | 128 | `accept()` | cierre de `Connection` |
| WebSocket | 64 | handshake `/lupa` válido, antes de `101` | cierre del transporte |
| Sesión LUPA | 32 | HELLO válido | `LupaSession.onClosed` |

Una conexión que todavía está leyendo HTTP no consume un slot de sesión.
Un WebSocket que espera HELLO consume capacidad WebSocket pero todavía no consume
una sesión LUPA.

Si no queda capacidad WebSocket y todavía no se realizó el upgrade, el servidor
responde HTTP 503. Si un HELLO válido encuentra las 32 sesiones ocupadas, se emite
`ERROR LIMIT_EXCEEDED` y se inicia cierre WebSocket 1013.

## Ejecutores

El grupo NIO ejecuta callbacks de transporte. El ejecutor general conserva una
cola acotada. Las operaciones potencialmente bloqueantes de sesión quedan separadas:

| Trabajo | Threads default | Cola default | Saturación |
|---|---:|---:|---|
| Estado/HTTP general | hasta 8 | 256 | rechazo |
| Teselas publicadas | hasta 4 | 64 | rechazo |
| Catálogo/manifiesto de OPEN | hasta 2 | 32 | rechazo |

Los ejecutores de almacenamiento usan `AbortPolicy`. No se utiliza
`CallerRunsPolicy`, por lo que saturar una cola nunca convierte un callback de red
en trabajador de disco.

La ruta HTTP `/api/catalog` todavía usa el worker HTTP general. Su separación se
revisará en el bloque de auditoría de almacenamiento de E22.

## Configuración añadida

- `--max-ws-connections`
- `--max-sessions`
- `--worker-threads`
- `--worker-queue-capacity`
- `--io-threads`
- `--disk-threads`
- `--disk-queue-capacity`
- `--metadata-threads`
- `--metadata-queue-capacity`
- `--ws-close-timeout-ms`

Se rechaza una configuración donde las sesiones superen los WebSocket o los
WebSocket superen las conexiones TCP/HTTP.

## Pendiente de E22

Todavía no se consideran terminados: timeout de HELLO, heartbeat, timeout de RELEASE,
timeout de escritura sin progreso, caché JPEG global, presupuesto global de bytes de
salida, fairness global entre sesiones, aislamiento completo del catálogo HTTP,
instrumentación final y pruebas de cliente lento.
