## Máquina de estados

```text
HTTP -> ESPERA_HELLO -> LISTA -> IMAGEN_ABIERTA -> CERRADA
```

Política:

| Entrada | Estado esperado | Resultado |
|---|---|---|
| HELLO inicial válido | ESPERA_HELLO | WELCOME y LISTA |
| HELLO repetido | cualquier estado posterior | cierre 1008 |
| OPEN válido | LISTA o IMAGEN_ABIERTA | MANIFEST, fija versión inmutable |
| OPEN antiguo/repetido | LISTA/IMAGEN_ABIERTA | ignorado |
| VIEW válido | IMAGEN_ABIERTA | sustituye plan y publica PLAN |
| VIEW inválido | IMAGEN_ABIERTA | ERROR sin consumir época |
| RELEASE válido | LISTA/IMAGEN_ABIERTA | libera reserva si delivery sigue pendiente |
| RELEASE duplicado/desconocido | LISTA/IMAGEN_ABIERTA | ignorado |
| mensaje después de cierre | CERRADA | ignorado |

JSON malformado, tipo de control desconocido y secuencias incompatibles cierran con 1008. Errores recuperables de aplicación usan ERROR LUPA.

## OPEN transaccional

La validación de catálogo/manifiesto se hace fuera del ejecutor serial. La confirmación vuelve al ejecutor de sesión.

Una respuesta tardía de un OPEN anterior no puede reemplazar una intención posterior ya aceptada. Un OPEN posterior que falla almacenamiento no consume su época ni destruye la imagen válida anterior.

La versión abierta queda fijada por `imageId + imageVersion`; cambios futuros del catálogo no alteran esa sesión abierta.

## VIEW y planificación

La validación se encapsula en `ViewRequest` antes de mutar estado.

Reglas principales:

- `rect` en coordenadas de imagen original;
- `viewportPx` en píxeles físicos del área real de imagen;
- `detailOffset` ∈ {-2,-1,0};
- `mode` ∈ {uniform,focus};
- `focus=null` en uniform;
- radio máximo: 512 píxeles físicos;
- viewport máximo: 8,294,400 píxeles.

### Nivel automático

Se elige el primer nivel real del manifiesto que satisface ambos ejes de la demanda:

```text
rectWidth  * levelWidth  >= viewportWidth  * originalWidth
rectHeight * levelHeight >= viewportHeight * originalHeight
```

No se asumen potencias exactas de dos.

Luego:

```text
requestedApplied = max(0, automaticLevel + detailOffset)
```

Si el plan completo no cabe, se recalcula a un nivel menor; no se trunca arbitrariamente la lista.

### Selección espacial

La conversión usa dimensiones exactas del nivel y límites semiabiertos para no pedir una columna/fila extra en un borde exacto.

El coste bitmap es:

```text
4 * tileWidth * tileHeight
```

con dimensiones reales de teselas de borde.

Límites:

- 64 MiB de referencia por cliente;
- 16 MiB reservados para miniatura/transitorios;
- máximo 512 descriptores;
- hasta 16 entregas pendientes;
- ventana comprimida separada del presupuesto bitmap.

## Focus

Política concretada:

```text
contextLevel = max(0, appliedLevel - 1)
```

El radio físico se transforma con escalas X/Y independientes:

```text
radiusOriginalX = radiusPx * rect.width  / viewportPx.width
radiusOriginalY = radiusPx * rect.height / viewportPx.height
```

Por tanto un círculo de pantalla puede ser una elipse en coordenadas originales.

Orden:

1. miniatura inicial cuando corresponda;
2. contexto mínimo;
3. foco visible;
4. resto de contexto visible.

Las identidades `z/x/y` se deduplican.

## Ciclo interno de entrega

Estados internos principales:

```text
seleccionada
-> lectura
-> preparada
-> RESERVED_QUEUED
-> COMMITTED
-> WRITTEN_AWAITING_RELEASE
-> RELEASED
```

Una entrega puede terminar en CANCELLED si todavía no fue comprometida.

Punto de compromiso: primer `AsynchronousSocketChannel.write(...)` del frame WebSocket. Antes de ese punto, el frame puede retirarse de la cola; después no se promete retirar bytes.

## Créditos

La reserva exacta es:

```text
4 + H + payloadBytes
```

No incluye overhead WebSocket.

Invariante:

```text
freeWindowBytes + sum(pendingReservations) = negotiatedWindowBytes
```

Se mantiene tras VIEW, OPEN, cancelación, RELEASE, RELEASE duplicado/desconocido y callbacks tardíos.

Una entrega antigua ya comprometida conserva su reserva hasta RELEASE o cierre. Cambiar época o imagen no purga automáticamente esas reservas.

`deliveryId` es monotónico por conexión y no se reutiliza. Al agotar 2147483647 se requiere una sesión nueva.

## DONE

DONE se emite únicamente cuando terminaron las escrituras de todos los TILE del plan vigente.

No espera:

- RELEASE;
- decodificación;
- dibujo;
- composición final del cliente.

No se emite para un plan cancelado ni para un plan que falló por lectura.

## Errores LUPA v1

| Condición | Código |
|---|---|
| versión no soportada | VERSION_UNSUPPORTED |
| VIEW inválida | BAD_VIEW |
| imagen no publicada | IMAGE_NOT_FOUND |
| publicación/manifiesto no disponible | IMAGE_NOT_READY |
| presupuesto/límite agotado | LIMIT_EXCEEDED |
| lectura de TILE falló | INTERNAL_READ_ERROR |

No se exponen rutas privadas ni stack traces.

## Pruebas

Cobertura añadida:

- geometría con dimensiones impares;
- offsets -2/-1/0;
- foco central/borde/no intersección;
- relación de aspecto desigual;
- reducción por presupuesto;
- límite de 512 descriptores;
- deduplicación;
- VIEW durante lectura;
- cancelación precommit;
- escritura ya comprometida;
- RELEASE antes de callback;
- OPEN asíncrono fuera de orden;
- época alta inválida no consumida;
- deliveryId máximo;
- dos sesiones independientes;
- error de lectura actual y obsoleto;
- DONE cancelado/actual;
- secuencia determinista del invariante de créditos.
