## Decisiones de integración

1. El modo normal del servidor usa `catalog=file`; la fixture queda disponible solo mediante `--catalog=fixture` para pruebas/demostración explícita.
2. Importador y servidor comparten `--data-root`. El servidor deriva el catálogo como `<data-root>/catalog.json` y normaliza la ruta absoluta al arrancar.
3. Para evitar depender accidentalmente del directorio actual, la demostración usa un `--data-root` absoluto.
4. `FileCatalogSource` lee y valida `catalog.json` en cada solicitud. No existe una caché de servidor que oculte una publicación nueva.
5. A19 sustituye el catálogo de forma atómica; por ello el servidor observa el catálogo anterior o el nuevo, no una escritura parcial.
6. Catálogo ausente/corrupto/ilegible produce `503 Service Unavailable`. Un catálogo vacío válido produce `200` con `images: []`; no hay fallback silencioso a fixture.
7. El trabajo de disco de `/api/catalog` continúa ejecutándose en el executor acotado de E19, no dentro del callback de red NIO.2.
8. `PublishedImageStore` verifica la unión catálogo → manifiesto y resuelve rutas internas de teselas a partir de identificadores validados. No expone esas rutas por HTTP.
9. El objeto `OpenedImage` conserva `imageVersion`; una publicación posterior puede cambiar el catálogo vigente sin invalidar la versión inmutable ya abierta.

## Contrato A19 → E19

| Elemento | Estado integrado |
|---|---|
| catálogo | `<data-root>/catalog.json` |
| versión vigente | entrada `imageId + imageVersion` del catálogo |
| manifiesto | `pyramids/<imageId>/<imageVersion>/manifest.json` |
| tesela interna | `pyramids/<imageId>/<imageVersion>/tiles/<z>/<x>_<y>.jpg` |
| tileSize | 256 |
| overlap/depth | 0 / `onetile` |
| nivel 0 | cabe en una tesela |
| nivel máximo | resolución original normalizada |
| originales | privados bajo `originals/` |
| staging | privado bajo `staging/` |

El manifiesto persistido no incorpora `epoch`; ese campo pertenece al futuro mensaje LUPA `MANIFEST`.

## Comandos reales

### 1. Compilar y probar

```bash
cd /home/erwin/PRJIMA
mvn clean verify package
```

Offline, después de la preparación ya realizada en E19/A19:

```bash
mvn -o clean verify package
```

### 2. Arrancar con almacenamiento real

```bash
java -jar target/lupa.jar \
  --host=127.0.0.1 \
  --port=8081 \
  --data-root=/home/erwin/PRJIMA/data
```

La salida registra el `dataRoot` resuelto. Ya no es necesario seleccionar `--catalog=file`, porque es el modo normal de I19.

Fixture explícita, solo cuando se necesite:

```bash
java -jar target/lupa.jar --catalog=fixture --port=8081
```

### 3. GET y HEAD del catálogo real

```bash
curl -i http://127.0.0.1:8081/api/catalog
curl -I http://127.0.0.1:8081/api/catalog
```

GET debe responder `200`, `Content-Type: application/json; charset=utf-8`, `Cache-Control: no-store` y el catálogo real. HEAD conserva las cabeceras y `Content-Length` de GET, sin cuerpo.

### 4. Comprobar almacenamiento real existente

```bash
cat /home/erwin/PRJIMA/data/catalog.json
cat /home/erwin/PRJIMA/data/pyramids/prueba-local/v1/manifest.json
vipsheader /home/erwin/PRJIMA/data/pyramids/prueba-local/v1/tiles/0/0_0.jpg
vipsheader /home/erwin/PRJIMA/data/pyramids/prueba-local/v1/tiles/3/4_3.jpg
```

En la comprobación inicial, las dos teselas reales tenían dimensiones `137x102` y `72x47`, respectivamente.

### 5. Nueva publicación visible sin reiniciar servidor

Con el servidor anterior todavía ejecutándose, en otra terminal:

```bash
java -cp target/lupa.jar gt.lupa.ingest.IngestApplication import \
  --original=/home/erwin/PRJIMA/prueba-real.jpg \
  --image-id=i19-live \
  --display-name="I19 live publication" \
  --license-ref="Fotografia propia de Erwin; uso autorizado para prueba I19" \
  --data-root=/home/erwin/PRJIMA/data \
  --vips=vips \
  --vipsheader=vipsheader \
  --timeout-seconds=600 \
  --jpeg-quality=85

curl -i http://127.0.0.1:8081/api/catalog
```

Si `i19-live` ya existe, A19 publica una versión nueva e inmutable; la petición posterior debe mostrar la nueva versión vigente sin reiniciar Java.

### 6. Rutas privadas

```bash
curl -i http://127.0.0.1:8081/data/originals/prueba-local/v1/source.jpg
curl -i http://127.0.0.1:8081/data/staging/job-x
curl -i http://127.0.0.1:8081/data/pyramids/prueba-local/v1/manifest.json
```

Las tres deben responder `404`.

### 7. `/lupa`

```bash
curl -i http://127.0.0.1:8081/lupa
```

Permanece reservado/no implementado funcionalmente en esta fase; I19 no introduce `101 Switching Protocols` ficticio.
