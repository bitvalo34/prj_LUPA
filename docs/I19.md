## Decisiones de integración

1. El modo normal del servidor usa `catalog=file`; la fixture queda disponible solo mediante `--catalog=fixture` para pruebas/demostración explícita.
2. Importador y servidor comparten `--data-root`. El servidor deriva el catálogo como `<data-root>/catalog.json` y normaliza la ruta absoluta al arrancar.
3. Para evitar depender accidentalmente del directorio actual, la demostración usa un `--data-root` absoluto.
4. `FileCatalogSource` lee y valida `catalog.json` en cada solicitud. No existe una caché de servidor que oculte una publicación nueva.
5. A19 sustituye el catálogo de forma atómica; por ello el servidor observa el catálogo anterior o el nuevo, no una escritura parcial.
6. Catálogo ausente/corrupto/ilegible produce `503 Service Unavailable`. Un catálogo vacío válido produce `200` con `images: []`; no hay fallback silencioso a fixture.
7. El trabajo de disco de `/api/catalog` continúa ejecutándose en el executor acotado de E19, no dentro del callback de red NIO.2.
8. `PublishedImageStore` verifica la unión catálogo → manifiesto y resuelve rutas internas de teselas a partir de identificadores validados. No expone esas rutas por HTTP.
9. El objeto `OpenedImage` conserva `imageVersion`; una publicación posterior puede cambiar el catálogo vigente sin invalidar la versión inmutable ya abierta.

## Contrato A19 → E19

| Elemento | Estado integrado |
|---|---|
| catálogo | `<data-root>/catalog.json` |
| versión vigente | entrada `imageId + imageVersion` del catálogo |
| manifiesto | `pyramids/<imageId>/<imageVersion>/manifest.json` |
| tesela interna | `pyramids/<imageId>/<imageVersion>/tiles/<z>/<x>_<y>.jpg` |
| tileSize | 256 |
| overlap/depth | 0 / `onetile` |
| nivel 0 | cabe en una tesela |
| nivel máximo | resolución original normalizada |
| originales | privados bajo `originals/` |
| staging | privado bajo `staging/` |

El manifiesto persistido no incorpora `epoch`; ese campo pertenece al futuro mensaje LUPA `MANIFEST`.
