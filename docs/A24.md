Chrome 154.0.8037.98 headless en Windows 11 Home, servidor en WSL2/Ubuntu, AMD Ryzen 9 8940HX, 32 procesadores lógicos, 33342455808 bytes de RAM física. Viewport 1440x1000, DPR 1. Un cliente. Se conserva la LRU Java entre corridas, no se vacía la caché del SO y se deshabilita la caché HTTP. No se denomina campaña cold/warm.

Inicio: selección de imagen o clic para pasar de detalle -2 a 0. Final: primer `drawImage` de todas las entregas del plan vigente; se comprueban ids únicos contra `DONE.sentTiles`. Se registra además doble rAF como aproximación de oportunidad de presentación, no latencia física del monitor. ## Límites y deuda técnica identificada

1. `TileReadAdmission.flows` y `decodeWorker.minimumEpoch` no purgan todo el historial por conexión. Es deuda para operación prolongada con reconexiones reiteradas. Se documenta y no se promete consumo constante indefinido; este cierre documental no la convierte en un defecto corregido.
2. El hash del archivo oficial preparado procede de metadatos de origen, no de una nueva lectura local del ZIP/PNG completo. Las teselas publicadas se validaron localmente; son garantías diferentes.
3. No hay autenticación, TLS nativo, reanudación persistente ni arbitraje DRR de reintentos STA. No forman parte de las funcionalidades declaradas como implementadas.
4. El paquete A24 es documental/evidencial, no contiene las grandes imágenes ni sustituye el paquete completo offline de entrega.
