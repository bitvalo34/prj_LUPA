# A19 — Importador y almacenamiento

## Estado de implementación

Rama de trabajo: `feature/a19-ingest`, creada desde `main` después del cierre de E19.

El primer bloque implementa infraestructura que no depende de opciones específicas de una versión de libvips:

- CLI de preflight y validación de argumentos.
- resolución segura del layout `data/`;
- bloqueo exclusivo del importador;
- ejecución de procesos sin shell mediante `ProcessBuilder`;
- captura acotada de stdout/stderr;
- timeout y terminación de procesos iniciados por el trabajo;
- comprobación de libvips mediante `vips --version`;
- pruebas unitarias de los componentes anteriores.

La generación `dzsave`, inspección detallada del original, normalización, manifiesto, validación total de teselas y publicación se incorporan en el siguiente bloque después de verificar la versión y ayuda de libvips instalada en el WSL de Erwin. No se fijan flags no comprobados contra esa instalación.

## Preflight

Una vez instalado libvips y empaquetado el proyecto:

```bash
java -cp target/lupa.jar gt.lupa.ingest.IngestApplication preflight \
  --original="/ruta/privada/foto.jpg" \
  --image-id=sample-photo \
  --display-name="Sample photo" \
  --license-ref="Fotografía propia; permiso confirmado por Erwin" \
  --data-root=data \
  --vips=vips \
  --vipsheader=vipsheader
```

El comando falla con código distinto de cero si el original no es un archivo JPEG/TIFF regular y legible, el identificador es inválido, no puede inicializarse el almacenamiento o no puede ejecutarse libvips.
