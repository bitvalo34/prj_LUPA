# A19 — Importador y almacenamiento

## Estado actual

Rama de trabajo: `feature/a19-ingest`.

Entorno verificado en WSL2:

- Java Temurin 21.0.12.
- Maven 3.9.16.
- libvips 8.15.1.
- loaders JPEG y TIFF disponibles.
- `dzsave`, `autorot`, `colourspace`, `flatten` y `jpegsave` disponibles.
- repositorio y `/tmp` sobre el mismo filesystem ext4 durante la comprobación inicial.

## Comandos

### Preflight

```bash
java -cp target/lupa.jar gt.lupa.ingest.IngestApplication preflight \
  --original="/ruta/privada/foto.jpg" \
  --image-id=sample-photo \
  --display-name="Sample photo" \
  --license-ref="Fotografía propia; permiso confirmado" \
  --data-root=data
```

### Staging diagnóstico

`stage` genera una pirámide dentro de un trabajo temporal, pero no publica catálogo:

```bash
java -cp target/lupa.jar gt.lupa.ingest.IngestApplication stage \
  --original="/ruta/privada/foto.jpg" \
  --image-id=sample-photo \
  --display-name="Sample photo" \
  --license-ref="Fotografía propia; permiso confirmado" \
  --data-root=data \
  --jpeg-quality=85
```

### Importación completa y publicación

```bash
java -cp target/lupa.jar gt.lupa.ingest.IngestApplication import \
  --original="/ruta/privada/foto.jpg" \
  --image-id=sample-photo \
  --display-name="Sample photo" \
  --license-ref="Fotografía propia; permiso confirmado" \
  --data-root=data \
  --vips=vips \
  --vipsheader=vipsheader \
  --timeout-seconds=600 \
  --jpeg-quality=85
```

## Políticas de imagen

- Formatos públicos de entrada admitidos: JPEG y TIFF detectados por el loader real de libvips, no solo por la extensión.
- TIFF multipágina: rechazado cuando `n-pages > 1`.
- Orientación: se normaliza con `vips autorot`.
- Color: sRGB.
- Alpha: se aplana contra blanco `(255,255,255)` antes de crear JPEG.
- Original: se conserva en almacenamiento privado, sin modificarlo, y se verifica por SHA-256 antes/después de copiarlo.
- Calidad JPEG inicial: 85, configurable entre 40 y 95.

## Pirámide y manifiesto

- teselas de hasta 256 × 256;
- `overlap=0`;
- `depth=onetile`;
- nivel `z=0`: representación completa que cabe en una tesela;
- nivel máximo: resolución original ya normalizada;
- dimensiones entre niveles: división entre dos con redondeo hacia arriba.

El manifiesto persistido conserva estrictamente el contrato S19: los niveles contienen `z`, `width` y `height`. Las filas y columnas se derivan de esas dimensiones y `tileSize`; no se añaden como propiedades JSON porque el lector de E19 usa deserialización estricta.

## Validación integral antes de publicar

El comando `import` recorre todas las teselas esperadas de forma secuencial y acotada. Para cada una comprueba:

- nombre y coordenadas;
- ausencia de archivos o niveles inesperados;
- existencia de todas las coordenadas esperadas;
- firma JPEG;
- tamaño entre 1 y 262144 bytes;
- ancho y alto exactos, incluidos bordes;
- tres bandas RGB;
- decodificación completa mediante `vips avg`.

Una tesela que excede 262144 bytes hace fallar la importación completa. A19 no reduce silenciosamente la resolución ni cambia el límite del protocolo. Si se necesita, el administrador puede repetir la importación con menor `--jpeg-quality` dentro del rango documentado.

## Estructura publicada

```text
data/
  catalog.json
  originals/
    <imageId>/
      <imageVersion>/
        source.jpg | source.tiff
        import-metadata.json
  staging/
    .ingest.lock
    job-.../
  pyramids/
    <imageId>/
      <imageVersion>/
        manifest.json
        tiles/
          <z>/
            <x>_<y>.jpg
```

`data/originals`, `data/staging` y `data/pyramids` no son rutas HTTP públicas.

## Publicación consistente

1. Preflight e inspección del original.
2. Estimación conservadora de espacio. Es una estimación, no una cota estricta de memoria ni disco de libvips.
3. Bloqueo exclusivo del importador.
4. Generación completa dentro de `data/staging`.
5. Validación integral de manifiesto y teselas.
6. Copia privada del original y verificación SHA-256.
7. Movimiento atómico de la versión completa desde staging a `data/pyramids`.
8. Lectura y validación del catálogo anterior.
9. Escritura del catálogo temporal y reemplazo atómico de `data/catalog.json`.
10. Limpieza del staging perteneciente al trabajo.

Una versión publicada nunca se sobrescribe. Si falla antes del movimiento de la versión, el trabajo no se hace visible. Si el proceso falla después de mover una versión completa pero antes de reemplazar el catálogo, puede quedar una versión completa no referenciada; el catálogo anterior sigue válido. Ese directorio no se elimina mediante limpieza genérica.

La ausencia inicial de `catalog.json` equivale a un catálogo vacío válido. Un catálogo existente corrupto provoca error y no se sustituye por uno vacío.

## Integración con E19 / I19

E19 debe leer:

- `data/catalog.json`;
- `data/pyramids/<imageId>/<imageVersion>/manifest.json`.

El catálogo publica una sola versión vigente por `imageId`; las versiones anteriores permanecen inmutables en disco. Las teselas se resuelven internamente mediante:

```text
data/pyramids/<imageId>/<imageVersion>/tiles/<z>/<x>_<y>.jpg
```

I19 todavía debe sustituir la fixture del servidor por este catálogo real y comprobar el recorrido integrado. A19 por sí sola no declara I19 completada.
