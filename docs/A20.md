# A20 - Visor y cliente LUPA

**Responsable temporal de A20:** Erwin Arevalo (en sustitución de Adrian Romero únicamente durante esta fase).  
**Fecha de trabajo:** 20 de septiembre de 2026.  
**Dependencia:** I19; integración real disponible con E20 ya incorporado a `main`.

## Alcance

A20 implementa el recorrido de frontend necesario para seleccionar una imagen publicada, negociar LUPA v1, interpretar MANIFEST/PLAN/TILE, decodificar JPEG en un Web Worker y componer progresivamente la imagen en Canvas 2D.

No declara terminados I20 ni A21. Zoom/pan avanzados, `mode=focus`, `detailOffset` distinto de cero y la lente de interés quedan para tareas posteriores.

## Cambio tecnológico documentado

`Avances_LUPA.docx` propuso HTML/CSS/JavaScript sin framework. Para A20 se adopta **React + TypeScript + Vite**, autorizado para esta fase, conservando:

- API WebSocket nativa del navegador;
- Canvas 2D;
- Web Worker real con `createImageBitmap`;
- protocolo LUPA v1 sin cambios;
- Java 21 como único servidor de producción;
- recursos locales y funcionamiento sin solicitudes externas.

React se limita a catálogo, controles y estado visible. El flujo binario, Worker, cache de bitmaps y repintado Canvas viven en módulos imperativos y no almacenan JPEG/ImageBitmap en estado React.

Versiones fijadas por `frontend/package-lock.json`:

- React 19.3.0
- React DOM 19.3.0
- TypeScript 5.9.2
- Vite 8.3.0
- `@vitejs/plugin-react` 6.1.1
- Vitest 5.0.1

## Dirección visual: LUPA 64

La interfaz se presenta como una estación científica retro 3D de finales de los 90:

- carcasa marfil/gris cálido con biseles moldeados;
- cobalto, coral, amarillo cálido y verde como señales funcionales;
- símbolo propio de prisma/lente;
- catálogo como cartuchos físicos;
- visor como puerto de observación;
- telemetría separada del área científica;
- botón con recorrido visual de presión;
- inclinación 3D de selección;
- órbita geométrica ambiental discreta;
- animaciones mediante transform/opacidad y soporte `prefers-reduced-motion`.

No se aplican CRT, scanlines, pixelación, aberración cromática ni filtros de color sobre el Canvas de la imagen.

## Arquitectura del cliente

```text
React UI
  |
  +-- Catalog / status / accessibility
  |
  +-- LupaClient ----------------------------+
        |                                     |
        +-- WebSocketTransport (/lupa)        |
        +-- TILE envelope parser              |
        +-- DeliveryLedger                    |
        +-- BitmapBudget                      |
        +-- TraceBuffer                       |
        |                                     |
        +--> Decode Worker (max 2)             |
        |       createImageBitmap(JPEG)        |
        |                                     |
        +--> CanvasCompositor ----------------+
                requestAnimationFrame
                z=0 context -> detail
```

### Propiedad de recursos

- El mensaje `ArrayBuffer` pertenece inicialmente a `LupaClient`.
- Después de validar el envelope se transfiere al Worker y el hilo principal deja de usarlo.
- El Worker crea un `ImageBitmap`, valida dimensiones y lo transfiere al hilo principal.
- El compositor es propietario del bitmap almacenado y ejecuta `close()` al reemplazar, invalidar o destruir.
- RELEASE se envía una sola vez:
  - `displayed`: después del primer repintado real que incorporó el bitmap;
  - `discarded`: entrega válida que ya no se utiliza;
  - `failed`: entrega identificada cuyo procesamiento falló.

## Límites A20

| Recurso | Regla |
|---|---|
| Ventana solicitada | 1 MiB; se conserva el valor confirmado por WELCOME |
| Bitmaps administrados | 64 MiB |
| Contexto/transitorios | 16 MiB dentro de los 64 MiB |
| Detalle almacenado | 48 MiB |
| Canvas | máximo 8,294,400 píxeles |
| Worker activo | máximo 2 decodificaciones |
| Cola Worker | máximo 32 trabajos |
| JPEG en cola Worker | máximo 8 MiB |
| H de TILE | 1..4096 bytes |
| JPEG TILE | hasta 262144 bytes |
| Resize | VIEW consolidado tras 180 ms |

La memoria reportada por la UI es memoria administrada por LUPA (`4 * width * height` por bitmap), no toda la RAM/GPU del navegador.

## Vista inicial

La imagen se encaja completa sin deformación.

1. Se miden ancho/alto CSS del puerto de observación.
2. Se calcula DPR efectivo.
3. Si el Canvas excedería 8,294,400 píxeles, el DPR se reduce.
4. Se calcula el rectángulo real ocupado por la imagen dentro del Canvas.
5. Las bandas de encaje no se incluyen en `viewportPx`.
6. VIEW usa el rectángulo completo en coordenadas originales y el viewport físico de la imagen mostrada.

A20 no implementa pan/zoom avanzado.

## Estado y obsolescencia

Cada conexión tiene un `connectionId` local además del `epoch` de LUPA. De este modo, una respuesta tardía de un Worker de una conexión anterior no puede reaparecer si una nueva conexión reutiliza épocas o deliveryId.

Al cambiar imagen o VIEW:

- la época se incrementa inmediatamente;
- el Worker recibe invalidación;
- el detalle del Canvas anterior se retira;
- una entrega antigua identificable se confirma `discarded`;
- una respuesta vieja del Worker cierra su bitmap y no se dibuja.

DONE solo indica que E20 terminó de escribir el plan. La UI pasa a “Lista para observar” cuando además no quedan decodificaciones ni bitmaps pendientes del primer repintado.

## Modo muestra

El modo muestra se activa **únicamente** con:

```text
/?sample=1
```

No se activa automáticamente ante un error del servidor.

Usa los mismos parsers, Worker, presupuesto, ledger y compositor que la conexión real. Los JPEG de muestra se generan localmente mediante Canvas y se serializan en envelopes TILE reales. El primer plan incluye z=0; VIEW posteriores de la misma apertura no repiten la miniatura.

## Build y entrega desde Java

El código fuente frontend vive en `frontend/`.

`npm run build` escribe directamente en:

```text
src/main/resources/web/
```

con nombres de assets hashados. `HttpRouter` solo expone archivos de classpath bajo `/assets/` con extensiones permitidas; no convierte el servidor en un file server arbitrario.

Los artefactos de producción se mantienen en el repositorio para que el empaquetado Java normal no requiera Node:

```bash
mvn -o clean verify package
```

incluye el frontend ya construido dentro de `target/lupa.jar`.

### Preparación online del frontend

```bash
cd /home/erwin/PRJIMA/frontend
npm ci
npm test
npm run build
cd ..
mvn clean verify package
```

### Rebuild frontend sin Internet

Después de preparar la caché npm una vez:

```bash
cd /home/erwin/PRJIMA/frontend
rm -rf node_modules
npm ci --offline --ignore-scripts
npm test
npm run build
```

GitHub Actions verifica expresamente ese `npm ci --offline` después de poblar la caché en la misma ejecución.

## Ejecución real

```bash
cd /home/erwin/PRJIMA
java -jar target/lupa.jar \
  --host=127.0.0.1 \
  --port=8081 \
  --data-root=/home/erwin/PRJIMA/data

```

## Evidencia

La UI permite descargar una traza compacta que registra controles, épocas, identificadores y contadores, sin almacenar JPEG ni buffers.

Para cerrar A20 todavía se requiere evidencia visual del navegador real:

1. seleccionar `demo-auxiliar`;
2. esperar “Lista para observar”;
3. mantener catálogo y Canvas visibles;
4. abrir diagnóstico para comprobar PLAN/TILE/RELEASE/DONE;
5. guardar traza;
6. realizar captura de escritorio;
7. repetir revisión visual en una ventana estrecha.

No se considera una captura de mockup como evidencia.
