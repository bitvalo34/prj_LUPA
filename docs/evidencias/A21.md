## Diagnóstico y corrección de la diferencia inicial

Las capturas estabilizadas muestran de forma consistente una diferencia de una unidad:

```text
TILE recibidos = Dibujados + 1
TILE recibidos = RELEASE + 1
```

La traza corta aisló la causa. Al abrir el visor como `http://<IP-WSL>:8081`, Chrome no expone `crypto.subtle` porque el origen no es un contexto seguro. El cálculo diagnóstico del SHA-256 del primer TILE accedía directamente a esa API y lanzaba una excepción síncrona antes de registrar, decodificar y liberar la miniatura. Los TILE siguientes no repetían el cálculo y funcionaban normalmente.

La corrección encapsula el SHA-256 como diagnóstico opcional: cuando Web Crypto no está disponible registra `digest no disponible en este contexto` y continúa el flujo normal del TILE. Así, una capacidad diagnóstica del navegador ya no puede interrumpir el protocolo ni dejar una entrega sin RELEASE.

La captura estabilizada confirmó además `TILE recibidos = Dibujados = RELEASE = 49`, cero descartes, cero decodificaciones pendientes, cero pinturas pendientes y 3.1 MiB de memoria administrada. La diferencia inicial de una unidad quedó resuelta.
