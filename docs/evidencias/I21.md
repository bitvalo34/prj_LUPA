# I21 — Evidencia de integración

## Estado

I21 integra E21 + A21 sobre un único servidor Java y fue ejercitada en dos navegadores
reales distintos.

## Base

- Rama: `feature/i21-integration`.
- Navegadores: Chrome 153.0.8010.52 y Edge 153.0.4234.48.
- Servidor: un único proceso Java en `127.0.0.1:8081`.
- Principal: `demo-grande-reference/v1` (40000×30131, maxLevel 8).
- Cambio de imagen: `demo-auxiliar/v1` (1096×815, maxLevel 3).

## I21-01 — independencia A/B

### Chrome A

Se observó una sesión de foco/detalle alto con época y región propias.

### Edge B

Se mantuvo uniform/detail=-2 mientras Chrome navegaba. En la traza corta de B no
aparecieron nuevas VIEW provocadas por las acciones de A.

**Resultado:** PASS.

## I21-02 — trabajo obsoleto

Se habilitó temporalmente:

```text
?i21DecodeDelayMs=750
```

La traza registró:

- `trabajo invalidado en cola`;
- `época obsoleta después de decodificar`;
- RELEASE `discarded` para las entregas afectadas.

No se volvió a marcar esas entregas como displayed.

**Resultado:** PASS.

## I21-03 — resolución efectiva

Misma imagen y región:

| detailOffset | PLAN observado |
|---:|---:|
| 0 | z3 |
| -1 | z2 |
| -2 | z1 |
| 0 otra vez | z3 con nuevas TILE |

**Resultado:** PASS.

## I21-04 — foco

Observado en navegador:

- centro;
- borde;
- esquina;
- radio 512 px;
- foco fuera de la región tras pan;
- retorno a uniform;
- `appliedLevel > contextLevel` cuando corresponde;
- contexto pintado antes que detalle.

El control A21 acota radio a 32–512 px. No se archivó una captura separada del valor
32 px.

**Resultado:** PASS, con la limitación documental indicada.

## I21-05 — créditos

Servidor arrancado con:

```bash
java -Dlupa.i21.diag=true -jar target/lupa.jar \
  --host=127.0.0.1 --port=8081 --data-root=/home/erwin/PRJIMA/data
```

Resumen observado:

```text
session=1  actividad real
session=2  segundo navegador
session=3  probe técnico
...
invariant=FAIL -> NINGUNO
```

El probe produjo:

```text
RELEASE duplicate=1
RELEASE unknown=2000000000
```

y el servidor registró ambos como:

```text
event=RELEASE_IGNORED
free=1048576
reserved=0
pending=0
window=1048576
invariant=OK
```

**Resultado:** PASS.

## I21-06 — imagen, memoria y reconexión

### Cambio de imagen en la misma conexión

Secuencia observada en Chrome:

```text
OPEN epoch=34 demo-auxiliar
VIEW epoch=35
...
OPEN epoch=36 demo-grande-reference
VIEW epoch=37
```

Los deliveryId continuaron de 265...285 y luego 286...306: cambiar de imagen no
reinició la secuencia de entregas.

Estado visual observado:

- demo-auxiliar: ~3.5 MiB administrados, decode=0, pintura=0;
- regreso a demo-grande-reference: ~4.6 MiB, decode=0, pintura=0;
- no quedaron píxeles de la imagen anterior.

### Reconexión

Log servidor relevante:

```text
session=4 event=CLOSE ... code=1000 reason=reconnect
session=6 event=OPEN_SOCKET state=ESPERA_HELLO
session=6 event=OPEN epoch=1 ... image=demo-grande-reference/v1
```

La sesión correspondiente al otro navegador permaneció viva y estable.

Capturas observadas:

- Edge: conexión #1, epoch 3, uniform, detail -2, ~360.9 KiB;
- Chrome después de reconectar: conexión #2, epoch 2, uniform, detail 0, ~4.6 MiB.

No apareció `invariant=FAIL`.

**Resultado:** PASS.

## DONE vs composición

En varias trazas DONE llegó mientras aún existían trabajos locales, por ejemplo
`decode>0` o `pintura>0`. El cliente no consideró la vista lista hasta completar el
Worker/compositor.

**Resultado:** PASS.
