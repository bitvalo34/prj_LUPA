# I20 — Primer recorrido completo

**Fecha de integración:** 20 de septiembre de 2026  
**Rama:** \`feature/i20-integration\`  
**Base:** \`main\` después de los merges de E20 (#8) y A20 (#9).

I20 no reconstruye E20 ni A20. Integra ambos y añade solamente instrumentación y una utilidad explícita de región parcial necesaria para demostrar la prueba vertical.

## Dependencias comprobadas en GitHub

- E20 PR #8: mergeado a \`main\`.
- A20 PR #9: mergeado a \`main\`.
- \`main\` al iniciar I20: \`8f34c6d5f5adc762394bcb8e70e429bbea535d9a\`.
- Frontend: React + TypeScript + Vite; WebSocket nativo, Worker e ImageBitmap, Canvas 2D.
- Backend: Java 21, NIO.2, WebSocket propio, LUPA v1.
- Producción: frontend construido dentro de \`src/main/resources/web\` y servido por el JAR Java.

## Comparación de contratos

| Elemento | Servidor E20 | Cliente A20 | Contrato acordado | Ajuste I20 |
|---|---|---|---|---|
| Ruta | \`/lupa\` | deriva \`/lupa\` del origen actual | \`/lupa\` | Ninguno |
| Subprotocolo | exige/selecciona \`lupa.v1\` | ofrece \`lupa.v1\` | \`lupa.v1\` | Ninguno |
| Origin | localhost o mismo host/puerto; no-Origin configurable | navegador usa mismo origen Java | origen explícito | Ninguno |
| Secuencia | HELLO→WELCOME→OPEN→MANIFEST→VIEW→PLAN→TILE/RELEASE→DONE | misma secuencia | LUPA v1 | Ninguno |
| WELCOME | ventana 512 KiB–1 MiB, maxTile 262144, maxInFlight 16 | valida límites negociados | mismos límites | Ninguno |
| MANIFEST | versión publicada y niveles exactos | valida imagen/versión/pirámide | S19 | Ninguno |
| VIEW | rect original, viewport físico, uniform/0/null en E20 | enviaba full-image uniform/0/null | E20 temporal | **Se añadió utilidad I20 de región central estrictamente menor** |
| Epoch | creciente, viejas ignoradas | creciente + connectionId local | 1..2147483647 | Ninguno |
| TILE | 4B H big-endian + JSON + JPEG | DataView + UTF-8 fatal + validación | H≤4096, JPEG≤262144 | Se añade hash SHA-256 de la primera TILE por OPEN a la traza |
| RELEASE | displayed/discarded/failed; reserva interna | exactamente uno tras pintar/descartar/fallar | sin bytes del cliente | Ninguno |
| DONE | fin de escrituras del plan | espera además decode+paint para “observar” | no significa render final | Ninguno |
| Recursos | Java/classpath; originales privados | mismo origen; sin CDN | offline | Ninguno |

No se detectó una incompatibilidad de protocolo bloqueante entre E20 y A20. El único hueco de I20 era que A20 solo emitía una VIEW de imagen completa, lo que impedía demostrar selección espacial sin adelantar A21. La utilidad “Probar región central I20” resuelve únicamente esa evidencia y está etiquetada como mecanismo de integración, no navegación terminada.

## Ajustes I20

### Región parcial de integración

El cliente puede solicitar una región centrada de aproximadamente 50% del ancho y 50% del alto de la imagen.

- sigue usando \`mode=uniform\`;
- \`detailOffset=0\`;
- \`focus=null\`;
- conserva la miniatura z=0 ya retenida;
- incrementa epoch;
- invalida trabajo local anterior;
- calcula \`viewportPx\` proporcional a la huella física de esa región en el Canvas;
- E20 selecciona únicamente teselas del nivel aplicado que intersectan el rectángulo.

“Restaurar vista completa” vuelve a emitir la VIEW completa. Ninguno de estos botones constituye zoom/pan de A21.

### Evidencia de una TILE

La primera TILE de cada OPEN registra en la traza:

\`\`\`text
LOCAL TILE_SHA256 delivery=... z=... x=... y=... bytes=... sha256=...
\`\`\`

Solo se copia esa primera carga comprimida para calcular SHA-256. No se registran JPEG completos ni buffers.

Comparación reproducible para \`demo-auxiliar\`, si la primera entrega es z=0/x=0/y=0:

\`\`\`bash
sha256sum data/pyramids/demo-auxiliar/v1/tiles/0/0_0.jpg
\`\`\`

El hash y los bytes deben coincidir con \`TILE_SHA256\`.

## Comprobación automatizada añadida

- matemática de región parcial y \`viewportPx\`;
- derivación same-origin de WebSocket;
- regresión E20: después del primer plan, una VIEW parcial envía solo la tesela de detalle intersectante en el fixture, no repite z=0 ni el nivel completo.

## Procedimiento manual de cierre

### 1. Entorno y build

\`\`\`bash
cd /home/erwin/PRJIMA
git status --short --branch
git fetch origin
git switch feature/i20-integration
git pull --ff-only origin feature/i20-integration

java -version
mvn -version
node --version

cd frontend
npm ci --offline --ignore-scripts
npm test
npm run build
cd ..
mvn -o clean verify package
\`\`\`

### 2. Arranque final desde Java

\`\`\`bash
java -jar target/lupa.jar \
  --host=127.0.0.1 \
  --port=8081 \
  --data-root=/home/erwin/PRJIMA/data \
  --ws-allow-no-origin=false
\`\`\`

Abrir una ventana nueva/incógnito en:

\`\`\`text
http://127.0.0.1:8081/
\`\`\`

No usar \`?sample=1\`.

### 3. Recorrido completo

Seleccionar \`demo-auxiliar\` y esperar “Lista para observar”.

Conservar evidencia de:

- MANIFEST real;
- PLAN;
- z=0;
- detalle;
- DONE;
- RELEASE;
- decode=0 y pintura=0 al finalizar.

### 4. Región parcial

Pulsar **Probar región central I20**.

La traza debe mostrar una nueva VIEW con:

\`\`\`text
rect=x,y,width,height viewport=WxH
\`\`\`

donde width/height sean menores que 1096×815.

Después:

- PLAN usa la nueva epoch;
- las TILE de detalle pertenecen solo a coordenadas intersectantes;
- z=0 no se repite en esta segunda VIEW;
- \`DONE sentTiles\` debe ser menor que el plan completo;
- no deben recibirse todas las 20 teselas z=3 usadas por la vista completa de \`demo-auxiliar\`.

### 5. Comparación de hash

Buscar \`TILE_SHA256\` en diagnóstico o traza descargada y ejecutar:

\`\`\`bash
sha256sum /home/erwin/PRJIMA/data/pyramids/demo-auxiliar/v1/tiles/0/0_0.jpg
wc -c /home/erwin/PRJIMA/data/pyramids/demo-auxiliar/v1/tiles/0/0_0.jpg
\`\`\`

Comparar SHA-256 y cantidad de bytes.

### 6. Tráfico y privacidad

Con DevTools → Network, “Disable cache” activado, recargar una pestaña limpia.

Solicitudes esperadas de la aplicación:

- \`/\`;
- assets JS/CSS locales;
- Worker JS local;
- \`/api/catalog\`;
- \`/lupa\` WebSocket.

No deben existir solicitudes de aplicación a dominios externos ni rutas HTTP para originales/teselas.

Comprobar además:

\`\`\`bash
curl -i http://127.0.0.1:8081/data/originals/secret.jpg
curl -i http://127.0.0.1:8081/data/staging/anything
curl -i http://127.0.0.1:8081/data/pyramids/demo-auxiliar/v1/tiles/0/0_0.jpg
\`\`\`

Las tres deben responder 404.

### 7. Offline

Con el servidor todavía activo:

1. cerrar la pestaña;
2. desconectar Wi-Fi/acceso externo del host Windows, sin detener WSL ni localhost;
3. abrir una ventana incógnita nueva;
4. visitar \`http://127.0.0.1:8081/\`;
5. seleccionar \`demo-auxiliar\`;
6. repetir el recorrido.

No utilizar DevTools “Offline” porque también puede bloquear localhost.

### 8. Regresiones manuales mínimas

- seleccionar otra imagen mientras todavía hay actividad y confirmar que no reaparece detalle de la anterior;
- pulsar Reconectar y comprobar que la conexión local cambia y vuelve a abrir la imagen al seleccionarla;
- abrir una segunda pestaña y comprobar contadores/conexión independientes;
- confirmar ausencia de errores funcionales en Console.

## Evidencia pendiente

Este documento distingue las comprobaciones de código/CI de las que deben realizarse en el equipo de Erwin. I20 no se marcará completa hasta recibir:

- build final del branch I20;
- traza del plan completo + plan parcial;
- hash comparado;

- prueba offline;
- captura del Canvas tras región parcial;
- comprobaciones básicas de reconexión/cambio de imagen/dos pestañas.

## Fuera de alcance

I20 no implementa:

- navegación completa;
- pan/zoom;
- foco/lente;
- \`detailOffset=-1/-2\`;
- heartbeat avanzado;
- campaña de carga.

Esas funciones siguen perteneciendo a E21/A21/E22 y posteriores.

## Evidencia real verificada en WSL/navegador

### Build local

En el WSL de Erwin:

- Vitest: **6 archivos / 23 pruebas aprobadas**.
- `mvn -o clean verify package`: **BUILD SUCCESS**.

### Plan completo — demo-auxiliar/v1

La traza real preservada en `docs/evidencias/I20-demo-auxiliar-trace.txt` muestra:

- OPEN epoch=1;
- MANIFEST `demo-auxiliar/v1`;
- VIEW epoch=2 `rect=0,0,1096,815 viewport=892x663`;
- PLAN `appliedLevel=3`;
- TILE delivery 1: z=0, 137×102, 4133 bytes;
- 20 TILE z=3 adicionales, incluidas teselas de borde de 72 px y 47 px;
- DONE `sentTiles=21`;
- al llegar DONE aún quedaban `decode=8 pintura=0`;
- las RELEASE pendientes continuaron después de DONE.

Esto verifica que DONE sigue significando fin de envío y no fin del renderizado local.

### Hash de TILE publicada

La primera TILE registró:

```text
bytes=4133
sha256=1db9f08ef488717d0b2d441d532e018f96e19250bb798c4359344b1e85db6736
```

En el equipo se ejecutó:

```bash
sha256sum data/pyramids/demo-auxiliar/v1/tiles/0/0_0.jpg
wc -c data/pyramids/demo-auxiliar/v1/tiles/0/0_0.jpg
```

y se obtuvo exactamente el mismo SHA-256 y **4133 bytes**. Por tanto, la carga binaria recibida coincide con el JPEG publicado.

### Región parcial

La utilidad I20 emitió:

```text
VIEW epoch=3 imageId=demo-auxiliar imageVersion=v1
rect=274,204,548,407 viewport=446x331
```

E20 respondió con `PLAN appliedLevel=3` y exactamente estas 9 teselas:

```text
(x=1,y=0) (x=2,y=0) (x=3,y=0)
(x=1,y=1) (x=2,y=1) (x=3,y=1)
(x=1,y=2) (x=2,y=2) (x=3,y=2)
```

No se repitió z=0. DONE informó `sentTiles=9`. Hubo exactamente 9 RELEASE `displayed`.

La geometría es correcta para la región original `[274,822) × [204,611)` con tileSize=256: intersecta x=1..3 e y=0..2. El plan parcial no envió las 20 teselas de detalle de la vista completa.

Al llegar DONE todavía había `decode=1 pintura=8`, y las 9 RELEASE ocurrieron después, confirmando nuevamente la separación entre fin de transmisión y fin de procesamiento local.
